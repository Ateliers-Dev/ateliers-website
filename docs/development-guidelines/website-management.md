# Website Management

**方針確定日：2026年11月13日（日本時間）**

## 1. 目的と基本方針

本ドキュメントは、Ateliers-Dev が運営するウェブサイトの目的、情報分類、公開方針および維持管理の基本原則を定めるものです。

Ateliers-Dev のウェブサイトは、OSS・ソフトウェア製品・技術研究・開発活動について、利用者や協力者が信頼できる情報を参照できる場所として運営します。

基本方針は以下のとおりです。

- 利用者が目的の情報へ容易にアクセスできる構成を優先する。
- 情報の性質と対象読者に応じて、掲載場所を区分する。
- 同じ情報の重複管理を避け、可能な限り原本を尊重する。
- サイト運営そのものが開発活動の過度な負担にならないようにする。
- 必要な情報から整備し、将来の利用を想定した過剰な構成は設けない。
- 運用上の課題や新たな要件が生じた場合に、方針を見直す。

本方針は上記確定日時点のものであり、将来のサイト構成や運用方法を恒久的に固定するものではありません。

## 2. コンテンツ分類

サイトの主要コンテンツは、次の4つに分類します。

### 2.1. Development Guidelines

Ateliers-Dev の複数のプロジェクトに共通する開発方針、規約、運用ルールを管理します。

主な内容は以下のとおりです。

- **GitHub Guidelines**：リポジトリ、ブランチ、Issue、Pull Request などの運用方針
- **Technical Policies**：設計原則、コーディング規約、テスト方針、セキュリティなど
- **Website Management**：サイトの情報分類、公開方針、運営ルール

特定のプロジェクトだけでなく、Ateliers-Dev 全体で再利用できる方針を対象とします。

### 2.2. Project Knowledge

各プロジェクトに関連する設計、技術検証、開発・運用情報などの知識を管理します。

主な内容は以下のとおりです。

- システム構成・アーキテクチャ
- 設計判断とその理由
- 技術検証・実験結果
- 実装上の注意事項
- トラブルシューティング
- 開発環境・運用手順

Project Knowledge は、完成した製品に限定しません。

研究、試作、検証段階のプロジェクトも対象とします。

### 2.3. Products

利用者や導入検討者に向けて、Ateliers-Dev が提供する製品、アプリケーション、OSS、ライブラリなどを紹介します。

主な内容は以下のとおりです。

- 製品概要と特徴
- 提供機能
- インストール・導入方法
- 利用ガイド
- 利用者向け API リファレンス
- 利用者向けリリースノート
- テスター・協力者の募集案内

正式リリース済みの製品だけでなく、Alpha や Beta など開発途中の製品も掲載できます。

その場合は、開発段階や利用上の制約を明示します。

GitHub Releases などに記録される詳細な変更履歴と、利用者向けリリースノートは、それぞれの目的に応じて使い分けます。

### 2.4. About

Ateliers-Dev の活動内容や参加方法を紹介します。

次の情報を扱います。

- **Overview**：活動概要、運営者、公開可能な連絡先
- **Projects**：主な活動領域・開発シリーズの紹介
- **Community**：参加方法、コミュニケーション手段の案内

About は組織や活動を知ってもらうための入口とし、詳細な技術文書やリポジトリ一覧は原則として掲載しません。

## 3. 情報の分類と配置基準

### 3.1. 分類の判断基準

新しい情報を公開する場合は、内容と対象読者から掲載場所を判断します。

| 情報の性質 | 原則的な掲載先 |
|---|---|
| 複数プロジェクトに共通する開発規約・方針 | Development Guidelines |
| 特定プロジェクトの設計・検証・運用情報 | Project Knowledge |
| 製品の特徴・利用方法・リリース情報 | Products |
| Ateliers-Dev の活動概要・参加方法 | About |
| 一般の技術者に共有する技術記事 | Zenn などの技術記事プラットフォーム |
| 短い近況・告知・協力者募集の呼びかけ | X などの SNS |
| ソースコードやリポジトリ固有の基本情報 | GitHub・各リポジトリの README |

一つの情報が複数の分類に関連する場合は、対象読者と目的を優先して判断します。

必要に応じて、別のカテゴリからリンクを設けます。

### 3.2. Project と Product の区別

Project は、開発、研究、検証などの目的を持った活動を指します。

Product は、利用者に提供する成果物を指します。

両者は必ずしも一対一で対応するものではありません。

一つの Project から複数の Product が生まれる場合や、一つの Product を複数の Project で開発・保守する場合があります。

また、すべての Project が Product になるとは限りません。

したがって、Project Knowledge と Products は名称を統一せず、それぞれ独立した責務を持つものとして扱います。

製品化された場合も、開発・研究の知識を Products に移動する必要はありません。

### 3.3. 情報の原本と重複管理

情報は、その内容を管理するうえで適切な場所を原本とします。

例えば、リポジトリ固有の概要や開発手順は README や当該リポジトリのドキュメントを原本とすることができます。

サイト側では、原本と同じ内容を手作業で重複管理することを原則として避けます。

必要に応じて、以下の方式を選択します。

- 原本へのリンクを掲載する。
- 利用者向けに必要な内容だけを要約して掲載する。
- GitHub Actions などを利用してドキュメントを自動連携する。

Project Knowledge を各開発リポジトリで管理し、Docusaurus に集約する方式も将来の選択肢とします。

ただし、具体的な連携方式やディレクトリ構成は、本方針では確定しません。

## 5. 活動領域とリポジトリの紹介

About / Projects では、リポジトリ単位ではなく、活動領域やシリーズ単位で紹介します。

例えば、次のような活動領域を扱います。

- **Ateliers AI**：AIオーケストレーション、AIエージェント、Skill 開発など
- **Ateliers Voice**：音声生成、音声再生、関連アプリケーションの開発など

各活動領域には、簡潔な概要と代表的なリポジトリを最大3件掲載します。

代表リポジトリは、活動状況、重要度、公開状況に応じて選定・変更します。

すべてのリポジトリを網羅することは目的としません。

詳細情報や全リポジトリの確認については、GitHub Organization および各リポジトリの README に案内します。

また、About / Projects は活動の紹介、Project Knowledge は技術情報の記録、Products は成果物の紹介として区別します。

## 6. 情報発信とコミュニティ

### 6.1. 情報発信の目的

Ateliers-Dev の対外的な情報発信は、主に次の2つを目的とします。

**開発活動の紹介と協力者の募集**

開発中のプロジェクトや製品を紹介し、利用者、テスター、協力開発者などとの接点を作ります。

**技術的な成果や知見の共有**

開発や研究で得た有用な技術情報を整理し、同じ分野に関心を持つ技術者へ共有します。

日常的な開発進捗や小さな実験結果を、継続的に記事化することは目的としません。

### 6.2. 発信媒体の役割

| 媒体 | 主な役割 |
|---|---|
| Ateliers-Dev Website | 活動・製品・技術情報の信頼できる参照先 |
| X | 短い告知、開発状況の共有、協力者募集、記事紹介 |
| Zenn など | 一般の技術者に役立つ技術記事の公開 |
| GitHub | ソースコード、README、Issue、Pull Request、Releases |
| Slack | 内部開発・運用、AIオーケストレーション等の通知 |
| Discord | 将来的な外部コミュニティの候補 |

サイト内に独立した Blog カテゴリは設けません。

技術記事は原則として Zenn などの外部プラットフォームを活用しますが、必要に応じてサイト内に掲載することも妨げません。

### 6.3. コミュニティの運用

GitHub Issues は、不具合報告、機能要望、正式な課題管理などに利用します。

Slack は内部運用と AI からの通知を目的とし、一般利用者向けコミュニティとしては扱いません。

Discord は将来的な外部コミュニティの候補ですが、現時点で設置や運用を必須としません。

Community ページには、実際に利用できる参加方法や問い合わせ先を案内します。

## 7. サイトの維持管理

### 7.1. 更新方針

サイトの定期的な記事投稿や更新を義務としません。

情報の変更、新しい製品の公開、利用者に伝えるべき内容が生じた場合に、必要な範囲で更新します。

更新頻度よりも、掲載情報の正確性と有用性を優先します。

### 7.2. 共通方針とサイト固有の技術情報

サイトの情報分類や公開方針など、Ateliers-Dev 全体の運営に関する共通ルールは Development Guidelines に記録します。

一方、Docusaurus の構成、GitHub Actions、ビルド、デプロイ、障害対応など、`ateliers-website` 固有の技術情報は Project Knowledge に記録します。

これにより、運営方針と具体的な実装・保守手順を区別します。

### 7.3. 将来的な拡張

現時点では、以下を独立したカテゴリとして設けません。

- FAQ
- Members
- Technical Notebook
- Blog

必要な情報は既存のカテゴリや外部サービスで扱い、独立させる明確な必要性が生じた場合に再検討します。

新しいカテゴリや運用ルールを追加する場合は、既存の分類で対応できないかを先に確認します。

## 8. 方針の見直し

本ドキュメントは、2026年11月13日（日本時間）時点で合意したサイト運営方針です。

実際の運用を通じて、情報の探しにくさ、管理負担、コンテンツの重複、新しい公開要件などが明らかになった場合は、必要に応じて改訂します。

方針の改訂では、次の観点を重視します。

- 利用者にとってわかりやすいか。
- 情報の責務と管理場所が明確か。
- 人間と AI の双方が判断・参照しやすいか。
- 継続的な維持管理が可能か。
- 変更による複雑化に見合う効果があるか。

**サイト構造や運用ルールを維持すること自体を目的とせず、Ateliers-Dev の開発活動と情報共有を支えることを優先します。**
