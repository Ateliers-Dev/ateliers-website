# AGENTS.md 作成ガイドライン

> 作成日: 2026-11-24
> 更新日: 2026-11-24
> 作成者: Codex

## 1. 目的と適用範囲

このガイドラインは、AI エージェントがリポジトリで作業する際に参照する `AGENTS.md` の新規作成・更新に適用します。`AGENTS.md` は作業上の指示を定める文書であり、製品仕様、設計の正本、詳細な運用手順の代わりにはしません。

共通のドキュメント作成規約は[ドキュメント作成ガイドライン](../documentation-guidelines.md)を参照してください。各リポジトリに明示された規約・取り決めがある場合は、そのリポジトリでは共通規約より上位として扱い、共通規約をオーバーライドできます。適用される上位の指示や安全要件には従ってください。

## 2. 作成・配置の原則

- 変更前に既存の `AGENTS.md`、リポジトリのREADME、関連ポリシーを確認し、既に書かれているルールを重複させないでください。
- リポジトリ全体に適用する規則はルートの `AGENTS.md` に置きます。特定のディレクトリだけに必要な指示は、その範囲を対象とする下位の `AGENTS.md` に置きます。
- 下位ファイルを作るのは、ルートの指示を繰り返さずに適用範囲を明確にできる場合に限ります。AI エージェントが規則の所在をたどれるよう、適用範囲と親指示との関係を明記します。
- 既にある開発方針や手順を `AGENTS.md` に全文複製せず、正本へのリンクと作業時に必要な短い指示を記載します。
- 新しいルールを加える前に、既存の決定との矛盾、他の指示との重複、適用範囲の曖昧さを確認します。判断が定まっていない案を確定した規則として記載しません。

## 3. 指示の書き方

- 具体的な作業条件、期待する行動、停止・報告条件を、短く直接的に記載します。
- 必須、推奨、禁止を言葉で区別し、曖昧な表現だけで義務や例外を示しません。
- 規則には、必要な場合に適用条件と例外を添えます。すべての作業に関係しない資料の一律参照や、不要な確認手順を求めません。
- 情報の正本を明確にし、詳細な仕様・方針・手順は該当する文書へリンクします。
- テスト、ビルド、レビューなどを求める場合は、対象・実施条件・成功判定を確認できる形で書きます。実行していない検証を実施済みと扱う指示や報告を求めません。
- 秘密情報、個人情報、外部サービス、破壊的操作などの扱いに制約がある場合は、必要な境界と判断・報告先を具体的に示します。
- 既存ルールの更新時は、対象ファイル以外への影響と、関連する索引・参照先への更新要否を確認します。

## 4. 言語と表記

- コミットメッセージは、原則として日本語で記述します。
- Pull Request のタイトルと本文は日本語で記述します。
- Issue のタイトルと本文は、原則として日本語で記述します。
- コード識別子、API 名、ファイル名は翻訳しません。
- 外部プロジェクトで作業するときは、そのプロジェクトの規約を優先します。

## 5. ルートREADME

リポジトリルートの README は仕様書ではなく、リポジトリの概要を簡潔に伝える文書です。初めて訪れた人にも分かる説明を優先し、長文化させません。

詳細な使い方、仕様、運用手順は `docs/` に置き、ルート README からリンクします。`AGENTS.md` の作成方法や詳細な規則をルート README に追加せず、適切な開発ドキュメントへ記載して参照します。

## 6. ドキュメントのメタデータ

Markdown 文書には、H1 の直後に作成日、更新日、作成者を引用行で記載します。

```markdown
# 文書タイトル

> 作成日: YYYY-MM-DD
> 更新日: YYYY-MM-DD
> 作成者: 名前
```

- 日付は日本標準時（JST）の `YYYY-MM-DD` 形式とします。既存文書の日時が不明な場合、ファイル履歴の最初のコミット日を作成日、最後の更新コミット日を更新日として使います。
- JST の日付を取得できない場合は UTC の日付を使い、値に `UTC` と明記します（例: `2026-11-18 UTC`）。
- 作成者は、AI エージェント自身の名前または識別名が分かる場合はそれを記載します。分からない場合は GitHub アカウント名を使い、それも分からない場合は `AI Agent` など識別可能な表記を使います。
- Docusaurus の Markdown / MDX では、必要な front matter の後に H1 を置き、その H1 の直後にメタデータを記載します。

## 7. 完了前の確認

`AGENTS.md` の新規作成・更新後は、変更範囲に応じて以下を確認します。

- 対象の作業範囲で指示が重複・矛盾せず、必要な正本への参照が有効であること。
- ルートREADMEに詳細な規則を重複して追加していないこと。
- 新規・更新した Markdown に指定のメタデータがあり、日付と作成者の根拠が適切であること。
- 既存のドキュメント索引やフォルダREADMEに掲載が必要な場合、それらも更新していること。

指示の妥当性を確認するために、無関係なコード変更や依存追加を行わないでください。
