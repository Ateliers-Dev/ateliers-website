# 記入例：Markdown 変換 CLI の MVP

> 作成日: 2026-11-17
> 更新日: 2026-11-18
> 作成者: Yuu503

> 以下はテンプレートの使い方を示す架空の例です。実在するプロジェクトの仕様ではありません。
>
> この例の MVP は、限定した入力形式と利用者を対象に、Markdown からプレーンテキストへの変換という主要な価値を実際の動作で示すものです。品質水準は一律ではなく、目的、要求・要件、提供対象、実行リスクに応じて定めます。ここでは簡易な評価に必要な範囲に絞ります。

## Must（必須項目）

### 1. 目的・成果物

- **目的・解決する課題：** 小さな Markdown 文書をプレーンテキストへ変換し、手作業で書式記号を取り除く手間を減らす。
- **対象利用者：** ローカルで文書を処理する開発者。
- **成果物：** UTF-8 の Markdown ファイルを受け取り、見出しと箇条書きを簡易変換して標準出力へ出す CLI。

### 2. 開発範囲・対象外

- **今回の範囲：** 評価用サンプルに含まれる見出し記号と箇条書き記号の除去、空行の維持、指定ファイルの読み込みと標準出力。
- **今回の対象外：** Markdown 全仕様への対応、HTML 変換、画像・表・リンクの整形、ディレクトリ一括処理。

### 3. 完了条件

- [ ] 指定したサンプル Markdown ファイルを読み込み、対応する書式記号を除去したテキストを出力できる。
- [ ] サンプルファイルで期待した変換結果を確認できる。
- [ ] 評価者が実行方法と対応範囲を理解し、主要な価値を評価できる。

### 4. 開発段階

| 段階 | 作業・成果 | 次へ進む条件 |
|---|---|---|
| 1. 評価範囲の固定 | 対象サンプル、対応する記号、期待出力を定める | 評価者が対象と変換例を確認できる |
| 2. MVP 実装 | サンプルを変換する CLI を実装 | 指定サンプルで主要な変換が動作する |
| 3. 価値の評価 | 実行方法を共有し、評価者が変換結果を確認する | 評価者が主要な価値を評価できる |

### 5. 検証方法

- **完了条件の確認方法：** サンプルファイルを使って手動実行し、出力が期待した変換結果と一致することを確認する。
- **レビュー・テスト：** サンプルに含まれる主要な変換と、評価者が実行・判断できる情報を確認する。自動テストや例外処理は一律の完了条件とせず、必要性があれば追加する。表やリンク対応の提案は範囲外の改善案として扱う。
- **失敗や未達の場合の記録・対応：** 期待した価値を示せなかった場合は、そのサンプルと結果、分かった原因を記録し、続行・範囲変更・中止を判断する。

### 6. 変更管理

- **変更を記録する場所・方法：** リポジトリの Issue と Pull Request に記録する。
- **範囲・完了条件・段階・検証への影響確認：** 新しい Markdown 機能を追加する提案は、MVP の範囲と完了条件への影響を確認してから扱う。
- **判断・承認者（プロジェクトの権限に応じて）：** リポジトリの変更権限を持つメンテナーが計画変更を判断する。

## Optional（任意項目・省略可能）

### 1. 要求仕様書

- **参照先または要約：** この計画の Must 項目と変換例を要求の原本とする。別の仕様書は作成しない。

### 2. アーキテクチャ・技術選定

- **構成・選定と理由：** 依存を増やさない小さな単一実行ファイルとし、変換ロジックを CLI 入出力から分離する。
