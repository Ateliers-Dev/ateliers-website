# Windows ローカルデータの保存場所と分類

> 作成日: 2026-11-23
> 更新日: 2026-11-23
> 作成者: Codex

## 保存場所の決め方

Windows のユーザー単位データには、.NET の既知フォルダーを使います。通常利用では次の API で場所を解決します。

```csharp
var localRoot = Environment.GetFolderPath(
    Environment.SpecialFolder.LocalApplicationData);
```

`LocalApplicationData` は現在の非ローミングユーザー向けアプリケーションデータの既知フォルダーです。パス文字列を直接組み立てて `%LOCALAPPDATA%` の値を仮定せず、解決結果が空の場合は保存を開始せず、明確なエラーとして扱います。

アプリケーションの標準ルートは、次の構造を推奨します。

```text
%LOCALAPPDATA%\Ateliers-Dev\<Application>├── data\
├── logs\
├── cache\
└── temp\
```

`<Application>` は製品の安定した識別名です。ディレクトリ名を変える場合は既存データの探索・移行方針を合わせて決めます。Debug と Release でデータを分ける場合は、各環境が別の明示的なサブディレクトリを使うなど、誤接続を防ぐ設計にします。

## データ分類

| データ | 置き場所 | 方針 |
|---|---|---|
| 端末固有の永続データ、データベース | `%LOCALAPPDATA%\Ateliers-Dev\<Application>\data\` | アプリの終了・更新後も保持する。製品が明示した削除・移行手順で扱う。 |
| 小容量で、端末間のローミングが意図される設定 | `%APPDATA%\Ateliers-Dev\<Application>\` | ローミングさせる必要がある場合に限る。容量の大きい履歴や DB を置かない。 |
| 診断ログ | `%LOCALAPPDATA%\Ateliers-Dev\<Application>\logs\` | 件数・サイズ・保持期間を決め、個人情報や機密本文を記録しない。 |
| 再生成可能なキャッシュ | `%LOCALAPPDATA%\Ateliers-Dev\<Application>\cache\` | 消去しても正しく再生成できることを保証する。上限または期限を設ける。 |
| 短命な処理中データ | `%LOCALAPPDATA%\Ateliers-Dev\<Application>\temp\` | 作業単位で隔離し、容量・件数・保持期限を管理する。使用中のファイルは回収しない。 |
| アプリケーションの実行ファイル | ユーザーデータとは別のインストール先 | データ領域と同じ場所に置かず、更新時にユーザーデータを巻き込まない。 |

`%APPDATA%` を使うかどうかは、設定を端末間で同期させる要件で決めます。既定は Local に置き、ローミングが明確に必要な小容量設定だけを Roaming に分けます。Microsoft の API は Local と Roaming を別の既知フォルダーとして定義しています。

## 遅延作成とパスの集約

- パス解決を一つの設定・パスサービスに集約し、機能ごとの文字列連結を避けます。
- コンストラクターや一覧表示だけではディレクトリを作成せず、最初の書き込み時に必要なディレクトリを作ります。
- テストではルートパスを注入可能にし、実ユーザーフォルダーにテストファイルを書かないようにします。
- 利用者が保存先を変更できる機能を追加する場合は、データ移行、失敗時の復旧、既存データ検出を別途設計します。
