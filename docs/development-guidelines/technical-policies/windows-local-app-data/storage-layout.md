# Windows ローカルデータの保存場所と分類

> 作成日: 2026-11-23
> 更新日: 2026-11-23
> 作成者: Codex

## 保存場所の選び方

Windows の既知フォルダーは、パスを固定値として組み立てず、利用するプラットフォーム API から解決します。.NET では次のように取得できます。

```csharp
var localRoot = Environment.GetFolderPath(
    Environment.SpecialFolder.LocalApplicationData);
var roamingRoot = Environment.GetFolderPath(
    Environment.SpecialFolder.ApplicationData);
```

`LocalApplicationData` は現在のユーザーの非ローミングアプリケーションデータ領域（通常の環境変数表記で `%LOCALAPPDATA%`）、`ApplicationData` はローミング用アプリケーションデータ領域（`%APPDATA%`）に対応します。実際のパスは Windows の設定や環境で変わり得るため、API の結果を使います。結果が空、利用不可、または書き込み不能なら、保存領域を勝手に別の場所へ切り替えず、理由を示して安全に失敗します。

## 用途別の標準配置案

```text
%LOCALAPPDATA%
└── <Publisher>
    └── <Application>
        ├── data
        ├── logs
        ├── records
        ├── cache
        └── temp
```

発行元とアプリケーションには安定した識別名を使い、名前の変更をデータ移行の対象として扱います。インストール先とユーザーデータ領域は分けます。

| データ分類 | 基本の配置 | 選定基準 |
|---|---|---|
| 端末固有の永続データ、将来のローカル DB | `%LOCALAPPDATA%\<Publisher>\<Application>\data\` | 大容量、端末固有、頻繁な更新、ローミング不要のデータ。 |
| ローミングを意図する設定 | `%APPDATA%\<Publisher>\<Application>\` | ユーザーが複数端末で共通設定を使う要件があり、小容量で端末依存情報を含まない場合に限る。 |
| 診断ログ | Local 領域の `logs\` | 障害調査に必要な期間を定め、サイズ・世代数を制限する。 |
| 実行記録・監査証跡 | Local 領域の `records\` または永続データ領域 | 診断ログとは別に保持期間、アクセス、削除、出力方法を定義する。 |
| 再生成可能なキャッシュ | Local 領域の `cache\` | 元データを失わず再生成できる場合に限り、上限・期限に従って破棄可能とする。 |
| 短命な処理データ | Local 領域の `temp\`、または OS の一時領域配下の専用サブディレクトリ | 作業の寿命を越えて保持せず、件数・容量・期間を制限して回収する。 |
| 実行ファイル | ユーザーデータとは別のインストール先 | 更新やアンインストールから利用者データを保護する。 |

`%APPDATA%` は同期やローミングの要件を自動的に満たす保証ではありません。環境による挙動と、設定の競合・容量・機密性への影響を確認してください。ローミング要件がない場合、設定も含め Local 領域を既定とします。大きな履歴、データベース、キャッシュ、ログ、一時データは Roaming 領域に置きません。

## Debug、Release、実行環境の分離

Debug と Release はビルド構成であり、開発・検証・本番の実行環境をそれだけで表すものではありません。必要な場合は、ビルド構成や明示的な環境識別子に基づく別のアプリケーション識別名またはデータルートを用い、画面・ログ・記録で現在のデータセットを判別できるようにします。

開発用の初期値は本番の記録や資格情報と分離します。本番データを開発環境で使う場合は、データの複製、秘匿化、書き込み可否を別途承認・設計します。環境判定不能時に本番データを暗黙に開く動作は避けます。環境名やビルド名を含むパスは一例であり、標準の固定形式は定めません。

## 解決と作成の責務

- 保存パスの解決を一つのコンポーネントに集約し、各機能で既知フォルダーの文字列を個別に連結しません。
- パス解決だけでディレクトリを作らず、必要な書き込み時に必要な場所だけを作ります。
- テストではルートを差し替え、実ユーザー領域にテストデータを書きません。
- 保存場所を変更可能にする場合は、容量、権限、バックアップ、移行失敗時の復旧を別途設計します。

データの変更・移行は[作成・更新・削除と移行](./lifecycle.md)、記録と監査の扱いは[実行記録と監査データ](./records-and-audit.md)を参照してください。
