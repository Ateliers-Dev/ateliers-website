# Windows ローカルデータの作成・更新・削除

> 作成日: 2026-11-23
> 更新日: 2026-11-23
> 作成者: Codex

## 推奨方針

保存データには、用途ごとに作成者、更新の単位、削除条件、復旧方法を定めます。アプリケーションの更新や終了だけを理由に永続データを削除しません。

| 種別 | 作成・更新 | 削除・保持 |
|---|---|---|
| 設定ファイル | サイズを制限し、同一ディレクトリの一時ファイルへ書いてから置換する。失敗時は旧ファイルを保持する。 | 初期化・リセット操作など、利用者が意図した操作で削除する。 |
| 永続データ・DB | トランザクションや対象形式に適した一貫性のある方法で更新する。 | 明示的なユーザー削除、製品固有の保持方針、または文書化した移行で扱う。単純な再インストールでは消さない。 |
| ログ | サイズ・件数・保持期限に達したときにローテーションまたは回収する。 | 必要な診断期間の後に古いものから削除する。 |
| キャッシュ | キャッシュキー単位で置き換え、再生成に必要な元データと混同しない。 | 再生成可能であることを確認したうえで、期限・上限に従って削除する。 |
| 一時データ | 作業 ID と用途で隔離し、書き込み途中と確定済みデータを区別する。 | 作業の完了・失敗、明示削除、期限切れ時に回収する。使用中のデータは残す。 |

## ファイルを安全に更新する

単一ファイルを更新する場合は、対象と同じボリューム上の一時ファイルに全内容を書き、書き込みを完了してから置換します。キャンセルや失敗では、一時ファイルをベストエフォートで削除し、既存の有効な対象ファイルを残します。ファイルの置換が対象 OS・ファイルシステムで原子的かどうかは、その API の契約と採用方法を確認してください。

設定など復旧可能な形式では、読み込み時にも最大サイズと形式の検証を行います。破損時に空の内容で上書きすると、復旧可能なデータを失うため、既定値で継続する場合も元ファイルの扱いを明示します。

## 削除、リセット、アンインストール

- 「キャッシュを消去」「設定を初期化」「すべての利用者データを削除」は別の操作として扱います。
- 永続データを削除する前に、対象範囲を利用者に示し、必要に応じてエクスポートやバックアップを提供します。
- アップデーターは既知のインストールファイルだけを対象にし、アプリケーションデータのルートを再帰削除しません。
- アンインストール時にデータを残すか削除するかを明示し、既定の動作と削除手順を利用者向け文書に記載します。
- 削除に失敗した場合は成功と報告せず、残ったデータの場所と再試行方法を示します。

## 保存先や形式を変えるとき

ディレクトリ名やデータ形式を変える前に、旧版の保存先を特定し、旧データが存在する場合の扱いを決めます。自動移行を実装するなら、少なくとも次を満たす必要があります。

1. 旧データを変更する前に、移行元を検証し、必要なバックアップを確保する。
2. 移行先へ段階的に書き込み、完了を識別できる状態を記録する。
3. 途中失敗や再起動後に安全に再試行でき、元データを失わない。
4. 移行完了前に旧データを削除しない。
5. 移行元・移行先・失敗時の復旧手順を利用者に説明する。

既存 CLI の説明では旧保存先のファイルを自動移動・削除しないことが確認できました。将来の変更では、これを一般的な移行方針と読み替えず、製品ごとに対応を判断します。

## 監査と診断

書き込み、削除、回収の失敗は、固定された操作名、例外の種類、必要最小限の結果を診断します。設定値、本文、資格情報、個人データをログへそのまま出さないようにします。データの内容を収集せずとも、失敗した場所と復旧の判断に必要な情報は記録できるようにします。

[一時データの上限と回収](./temporary-data.md)は短命データ固有の追加要件を定めます。
