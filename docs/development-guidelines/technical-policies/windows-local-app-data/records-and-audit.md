# Windows ローカル実行記録と監査データ

> 作成日: 2026-11-23
> 更新日: 2026-11-23
> 作成者: Codex

## 目的

将来、AI 協働の実行記録や成果を分析・改善・監査に活用できるデータ基盤を目指します。このページは必要なデータの性質と管理上の要件を定めます。データベースの採用やアクセス構成を決めるものではありません。

## 記録の種類を分ける

| 種類 | 主な目的 | 保持・運用 |
|---|---|---|
| 診断ログ | 障害調査、処理の状態把握 | サイズ・世代数・期間でローテーションし、古いものを削除する。本文や機密情報を避ける。 |
| 実行記録 | 一つの AI/自動処理の開始、実行中イベント、成果、終了状態を再構成する | 追跡に必要な識別子と時刻を持たせ、記録欠落や部分完了を表現できるようにする。保持期間と出力範囲を定める。 |
| 監査証跡 | 重要操作や権限判断を後から説明・検証する | 通常ログとは別のアクセス制御、保持期間、削除条件、完全性確認を定める。ローカル保存だけで改ざん不能・非否認性が得られるとはみなさない。 |

ログを長期間保持すれば監査記録になるわけではありません。分析・監査用の記録を通常ログの容量ローテーションで予告なく失わないよう、目的ごとに保存先と寿命を決めます。監査上の完全性や法的要件が必要な場合は、脅威モデル、保護境界、外部保管や署名などを別途設計します。

## 将来の記録契約

将来の記録形式は、保存実装から独立して扱える契約を目指します。必要性とプライバシーを確認しながら、次のような項目を検討します。

- 実行 ID、イベント ID、親子実行や相関の ID
- 記録時刻と、必要であれば発生時刻・取り込み時刻
- 実行主体、使用したエージェントやツールの識別情報
- 操作種別、状態遷移、結果、失敗分類
- 成果物や証跡への参照、内容のハッシュなど整合性確認に使う情報
- 記録スキーマのバージョン、生成元のバージョン
- データ分類、機密性、保持期限や削除状態

必要以上にプロンプト、会話本文、資格情報、個人情報を蓄積しません。本文を保存する場合は利用目的、同意・権限、マスキング、保存期間、削除とエクスポート、暗号化の要件を決めます。データの欠損、順不同、重複、部分成功を表現できる形を検討します。

## SQLite とアクセス方式は未決定

将来 SQLite をローカル永続ストアに使う可能性を見据えますが、この段階でスキーマや運用仕様を決めません。次の両案は検討候補に留めます。

- MCP が SQLite を直接利用する。
- MCP がローカル API を介して SQLite を利用する。

どちらも採用決定ではありません。利用者の導入手順、認証・アクセス制御、同時実行、バックアップ、更新配布、将来の別ストアへの移行などを比較して、別途設計判断を行います。データ利用側をファイルパスや特定 DB の内部形式に直接依存させない契約を検討しつつ、抽象化の方式自体も現時点で固定しません。

データ形式やスキーマを採用するときは、バージョン管理、互換性、移行と復旧の方針を定めます。[作成・更新・削除と移行](./lifecycle.md)を参照してください。
