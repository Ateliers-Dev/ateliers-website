# Windows ローカルデータ管理の概要

> 作成日: 2026-11-23
> 更新日: 2026-11-23
> 作成者: Codex

## 目的と適用範囲

Ateliers-Dev の Windows アプリケーションが設定、永続データ、ログ、キャッシュ、一時データをユーザー領域へ保存するときの共通方針を示します。これは Windows 専用の技術リファレンスです。

本書では、指定された2つの既存実装をコードで調査した**観測結果**と、今後の共通化に向けた**推奨方針**を分けます。観測結果は個別実装の現状を記録したもので、すべての製品に適用する規則ではありません。推奨方針は共通化の提案であり、各製品で採用するときは実装計画と移行影響を確認してください。

## 既存実装で観測したこと

| 観点 | コードで確認した事実 |
|---|---|
| ユーザー単位の基準領域 | .NET の `Environment.SpecialFolder.LocalApplicationData` からアプリケーション固有フォルダーを解決する実装がある。Windows の通常表記では `%LOCALAPPDATA%` 配下となる。 |
| 設定と端末固有データ | 一方の実装では小容量の設定を `%APPDATA%\Ateliers-Dev\Ai-Assistant[.Debug]\settings.json` に、端末固有データを `%LOCALAPPDATA%\Ateliers-Dev\Ai-Assistant[.Debug]\` に分ける。Debug と Release の保存先も分離している。 |
| データベース | 同じ実装は `data\assistant.db` を SQLite 用ファイルとして構成し、会話ストアからそのパスを利用する。ここでは SQLite 固有の接続・スキーマ設計は定めない。 |
| ログ、記事、キャッシュ、一時データ | ログは Local 配下でローテーションし、記事ファイルも Local 配下に保存する。キャッシュと一時データ用の場所は用途別に定義され、必要になるまでディレクトリを作らない設計である。 |
| 実行記録 | もう一方の CLI 実装は既定で `%LOCALAPPDATA%\Ateliers-Dev\Ai-Orchestrator\runs\` と `lifecycle.jsonl` を使う。実行ごとに `events.jsonl` とレポートを作成し、コマンド引数で別の出力先も指定できる。 |
| 旧保存先 | CLI の README は旧保存先の既存データを自動移動・削除しないと説明している。実装と説明の範囲では、旧データをそのまま残す扱いである。 |

この表はコードとリポジトリ内の利用者向け説明で確認できた範囲です。ユーザー端末上での実データの存在、全バージョンの挙動、過去の実行による残存ファイルまでは確認していません。

## 推奨する共通方針

1. Windows のアプリケーション固有データは、原則として `Environment.SpecialFolder.LocalApplicationData` を起点に解決します。
2. アプリケーションごとのディレクトリを作り、その下を `data`、`logs`、`cache`、`temp` など用途別に分けます。
3. フォルダーは必要になる時点で作成し、パスを解決しただけで空の保存領域を増やさないようにします。
4. 再インストールや更新で保持すべきデータと、再生成可能なデータを区別します。インストール先とユーザーデータ領域を混在させません。
5. ファイルの更新と削除は用途別のライフサイクルに従い、ユーザーデータを更新処理だけで暗黙に消さないようにします。
6. 一時データには容量、件数、保持期間の上限と安全な回収方法を設けます。

具体的なディレクトリ案は[保存場所とデータ分類](./storage-layout.md)、書き込みと移行の扱いは[作成・更新・削除と移行](./lifecycle.md)、一時領域は[一時データと容量管理](./temporary-data.md)を参照してください。

## 対象外

本書は SQLite のプロバイダー選定、接続オプション、テーブル設計、スキーマ更新、同時実行、WAL、バックアップや復旧の手順を定義しません。SQLite を含む永続データも、まず共通の保存場所とライフサイクルに従い、SQLite 固有の標準は別のリファレンスで設計します。
