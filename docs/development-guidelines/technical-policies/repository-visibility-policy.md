# Ateliers-Dev リポジトリの公開・非公開方針

> 作成日: 2026-11-23
> 更新日: 2026-11-23
> 作成者: Codex

## 1. 目的と適用範囲

本方針は、Ateliers-Dev が管理するリポジトリを公開または非公開にする際の基本的な考え方を定めます。

ここで扱う公開・非公開は、リポジトリの公開範囲に関する判断です。ウェブサイトへの情報掲載や、製品の提供状態とは区別します。

## 2. 公開価値を基準とする判断

リポジトリの公開・非公開は、機密情報が含まれるかどうかではなく、そのリポジトリを外部に公開する価値があるかどうかを主な基準として判断します。

PoC や MVP は、外部へ継続的に提供・保守するものではなく、公開する価値が低いものとして、原則非公開に分類します。

Ateliers は現時点で非営利を原則としています。そのため、プロダクトを外部に公開することによる営利上の利益保護は、公開・非公開の判断要素にしません。

公開価値を評価する際は、次のいずれかに該当することを公開候補とする判断材料にできます。

- 外部の開発者や利用者が成果物を利用・参照できる。
- 技術的な知識、設計、実装例などを共有できる。
- Ateliers の活動、理念、成果を外部に説明できる。
- 外部からのフィードバックや協働を受け入れる意義がある。

すべてに該当する必要はありません。これらは公開候補を検討するための例であり、公開設定の変更そのものを自動的に決めるものではありません。

## 3. 開発段階と公開状態

PoC や MVP は原則非公開としますが、開発段階だけでリポジトリの公開状態を固定しません。

例えば、PoC の内容を技術教材として整理するなど、外部に公開する価値が生まれた場合は、非公開から公開へ変更できます。反対に、完成したシステムであっても、外部に公開する価値がなければ非公開を認めます。

リポジトリは、非公開の状態で開発を進め、内容がある程度まとまった段階で公開に変更する運用も認めます。

## 4. 公開前の確認

リポジトリを公開する際は、次の事項を確認します。

- 公開する目的が明確であること。
- README などから、リポジトリの用途と開発状況を理解できること。
- ライセンスと外部著作物の取り扱いが整理されていること。
- 認証情報、個人情報、第三者の非公開情報など、公開してはいけない情報が含まれていないこと。

これらは公開前の情報管理確認であり、公開・非公開を分類する基準とは独立しています。機密情報の有無によって公開価値を判断しない原則は変わりません。

## 5. 公開後の保守とサポート

リポジトリを公開したことによって、継続的な保守やサポートの義務が自動的に発生するものとはしません。

必要に応じて、README などに開発状況やサポート範囲を記載します。

## 6. 公開状態を変更する権限

リポジトリの公開状態は、明確な方針または管理者の判断に基づいて変更します。

AI エージェントは公開価値を評価し、変更を提案できます。ただし、判断が曖昧な状態で公開設定を変更しません。

## 7. 非公開リポジトリの情報に関する前提

非公開リポジトリであっても、その情報は誰にでも見られうるものとして扱います。リポジトリを非公開にしていることを、情報を秘密に保つ手段として前提にしません。

したがって、機密情報の有無を理由にリポジトリの公開・非公開を分類しません。
